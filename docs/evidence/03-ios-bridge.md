# Evidence for chapter 03: Calling iOS from C# and back

What Phase 21 checked the chapter’s claims against, and where the outline was wrong. [PLAN.md](../PLAN.md), under “Decisions: evidence”, says what counts as evidence.

## Checked, and against what

Checked, and against what: the 6000.3.11f1 Trampoline (`main.mm` loading `UnityFramework` with `NSBundle`, `UnityAppController` and its display link, the Metal display link switched off, `UnityScene`, the listener headers, `IMPL_APP_CONTROLLER_SUBCLASS`, `Preprocessor.h`, the uncaught-exception handler, `process_symbols.sh` with `usymtool`) and its `Info.plist` template; device and Simulator exports of the probe (targets, plugin placement, importer defaults, `-ObjC` absent from `UnityFramework`, `GCC_ENABLE_OBJC_EXCEPTIONS = NO`); IL2CPP's source and the C++ it generated (string, `bool`, struct and array wrappers, `malloc` and `free`, the reverse wrapper's thread attach and missing handler, the two `NotSupportedException` messages, `GCHandle` slot reuse); runs in the iOS 27.0 Simulator with crash reports read from `.ips` files (threads by `sample`, argument buffers freed after the call, the returned-literal abort, the struct layout, instance, lambda and unattributed callbacks, a stale handle resolving to a newer object, callback exceptions ending the process, an `NSException` passing a C# `catch`, `EXC_BAD_ACCESS`, the `TCC` termination, `UnitySendMessage` copying its strings and arriving a frame later, the `-ObjC` failure and fix, a missing embed, Append against hand edits and a naive post-processor, `atos` with a matching and a foreign binary); an Editor batch call to `__Internal`; the Objective-C runtime's swizzle chaining on macOS; Swift 6.4 compiling `@c` and `@_cdecl`; and Unity's 6.3 pages, Apple's pages, SE-0495, QA1490 and `ld`'s manual for the rest. No device was used, so watchdog and memory terminations rest on Apple's documentation.

## Where the outline fell short

Where the outline fell short: it asked to free a context handle “on completion and on cancellation”, and freeing at cancellation while native code can still call back is the use-after-free itself, so the chapter frees once, in the final callback, and routes cancellation through native code. A missing embed does not crash in `dyld` in a Unity app: `UnityFramework` is loaded with `NSBundle`, so the app logs `Library not loaded` and exits with no crash report. `process_symbols.sh` uploads symbols to Unity's own service and is not in default exports. The outline did not cover the scene delegate, capture-free lambdas failing like instance methods, missing native functions failing at link time, `@try` needing `-fobjc-exceptions`, Objective-C exceptions passing C# `catch` blocks, resources in `Plugins/iOS` landing inside `UnityFramework.framework`, or the Simulator's watchdog allowance (598.63 seconds, against 19.97 in Apple's device example).
