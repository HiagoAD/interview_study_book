## Checked, and against what

### ci-pipeline-shape

- A project records the Editor version it was saved with in `ProjectSettings/ProjectVersion.txt`, as `m_EditorVersion`: confirmed in a Unity sample project’s file, [ProjectVersion.txt](https://raw.githubusercontent.com/Unity-Technologies/BoatAttack/master/ProjectSettings/ProjectVersion.txt), from 2020.3, and in the probe’s, whose first line is `m_EditorVersion: 6000.3.11f1`.
- The Editor’s arguments: confirmed on the 6000.3 [command-line page](https://docs.unity3d.com/6000.3/Documentation/Manual/EditorCommandLineArguments.html). In batch mode, “Unity runs command line arguments without the need for human interaction” and “suppresses dialog windows that require human interaction”; under `-nographics`, “Unity doesn’t initialize the graphics device”; `-projectPath` opens “the project at the given path”; `-logFile` “Specifies a file path location to which Unity writes the Editor log file”; `-quit` quits “after other commands have finished executing”; `-buildTarget` selects “an active build target to launch the Editor in”; and `-executeMethod` runs a static method of a script in an Editor folder. The page’s macOS example runs `/Applications/Unity/Hub/Editor/<Version>/Unity.app/Contents/MacOS/Unity`, the path that `ci/unity.sh` builds, and the script found 6000.3.11f1 there.
- The Test Framework’s command line: `-runTests`, `-testPlatform` (Edit Mode when omitted), `-testResults`, results in NUnit’s XML format, and “The Editor’s regular -quit command-line argument is not supported while tests are running”: confirmed on the 6000.3 manual’s [page for the runner](https://docs.unity3d.com/6000.3/Documentation/Manual/test-framework/reference-command-line.html). The container read the same arguments at version 1.4.6.
- The runner’s return codes, 0 for a pass, 2 for failed tests, 3 for a run error such as scripts that did not compile, and 0 for a run that executed no test: confirmed in `UnityEditor.TestRunner/CommandLineTest/Executer.cs` of version 1.6.0, the package built into the 6000.3.11f1 Editor, which maps `CompletedJobWithoutAnyTestsExecuted` to `Ok` as 1.4.6 did, and adds 4 for a test platform it cannot find. The Mac’s runs returned those codes.
- NUnit’s `test-run` element carries `total` and `passed`: confirmed in NUnit’s [result format](https://raw.githubusercontent.com/nunit/docs/master/docs/articles/nunit/technical-notes/usage/Test-Result-XML-Format.md), and in the results files of the Mac’s runs. Unity’s `total` includes skipped and inconclusive tests: `UnityEditor.TestRunner/Api/ResultsWriter.cs`, line 85, in the 1.6.0 package (“PassCount + FailCount + SkipCount + InconclusiveCount”); and the NUnit plugin fails a build for no result only when passed, failed and skipped are all 0 ([NUnitPublisher.java](https://raw.githubusercontent.com/jenkinsci/nunit-plugin/master/src/main/java/hudson/plugins/nunit/NUnitPublisher.java), lines 202 to 205), so a run of skipped tests alone passes both.
- `BuildPipeline.BuildPlayer(BuildPlayerOptions)` returns a `BuildReport`; it throws before building for an invalid output path or when a build is in progress, returns null after logging an `ArgumentException` from the build, and logs any other exception and calls `EditorApplication.Exit(1)`: confirmed in [BuildPipeline.bindings.cs](https://raw.githubusercontent.com/Unity-Technologies/UnityCsReference/6000.3.11f1/Editor/Mono/BuildPipeline.bindings.cs), lines 296 to 425. The overload that takes `BuildPlayerWithProfileOptions` throws for a null profile, makes the profile active, and builds the options from it before it calls the first (lines 319 to 327). `GetBuildPlayerOptionsFromActiveProfile`, in [BuildProfileModuleUtil.cs](https://raw.githubusercontent.com/Unity-Technologies/UnityCsReference/6000.3.11f1/Editor/Mono/BuildProfile/BuildProfileModuleUtil.cs), adds the profile’s Development Build and related settings to the options it is given, so `StrictMode` joins them. `BuildOptions.StrictMode`, “Force the build to fail when any errors are encountered”, is at line 105 of the first file.
- A failed build’s report can say `Unknown` rather than `Failed`: in the probe, a build whose scene list was empty stopped with “Cannot build untitled scene.” and “Build Finished, Result: Failure.”, and the script logged the returned report’s result as `Unknown`.
- The build script’s API, `BuildProfile.SetActiveBuildProfile` and `GetActiveBuildProfile`, `BuildPlayerWithProfileOptions`, `AssetDatabase.LoadAssetAtPath`, `EditorApplication.Exit(int)`, `BuildSummary.result`, `BuildResult.Succeeded`, `PlayerSettings.bundleVersion`, `PlayerSettings.Android.bundleVersionCode` (an `int`), `PlayerSettings.iOS.buildNumber` (a `string`) and `EditorUserBuildSettings.buildAppBundle`: both blocks compile against the 6000.3.11f1 Editor’s assemblies and ran in the probe.
- A variant is a build profile, Player settings calls act on the active profile, and chapter 10’s `StoreBuild` makes the profile active before it sets anything: chapter 10’s evidence, [10-variants-and-releases.md](10-variants-and-releases.md), runs 2, 4 and 4b.
- `PlayerSettings.bundleVersion` maps to `versionName` on Android and to `CFBundleShortVersionString` on iOS: confirmed on its [6000.3 reference page](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/PlayerSettings-bundleVersion.html).
- `Packages/packages-lock.json` holds the Package Manager’s resolution and belongs under source control: confirmed on the 6000.3 page on [lock files](https://docs.unity3d.com/6000.3/Documentation/Manual/upm-conflicts-auto.html).

### ci-jenkins-pipeline

- Controller, label, executor, node and workspace: confirmed in Jenkins’s [glossary source](https://raw.githubusercontent.com/jenkins-infra/jenkins.io/master/content/doc/book/glossary/index.adoc). Builds on the built-in node have the controller’s file access, and Jenkins advises agents instead: [controller-isolation.adoc](https://raw.githubusercontent.com/jenkins-infra/jenkins.io/master/content/doc/book/security/controller-isolation.adoc).
- The declarative syntax used by the chapter’s Jenkinsfile: `agent` with a label or a label expression, `agent none`, `parameters`, `options` (`buildDiscarder`, `disableConcurrentBuilds` with its queueing and `abortPrevious`, `timeout`), `environment`, `when` with `beforeAgent`, `parallel`, sequential `stages` inside a parallel branch, one of `steps`, `stages`, `parallel` or `matrix` per stage, `post` and the order and meaning of its conditions, and `input`: confirmed in [syntax.adoc](https://raw.githubusercontent.com/jenkins-infra/jenkins.io/master/content/doc/book/pipeline/syntax.adoc).
- `stash` keeps files for the same run only, is discarded at its end, is meant for small files with no hard limit but alternatives advised from somewhere between 5 and 100 MB, and costs the controller CPU because it is a compressed archive: confirmed in the step’s [help](https://raw.githubusercontent.com/jenkinsci/workflow-basic-steps-plugin/master/src/main/resources/org/jenkinsci/plugins/workflow/support/steps/stash/StashStep/help.html). `unstash` brings a stash from the controller into the workspace: [jenkinsfile.adoc](https://raw.githubusercontent.com/jenkins-infra/jenkins.io/master/content/doc/book/pipeline/jenkinsfile.adoc).
- `archiveArtifacts` saves files on the controller, keeps them as long as the build’s log, and fails the build when it archives nothing unless `allowEmptyArchive` is set: confirmed in core’s help files.
- `junit` reads JUnit XML and fails on no report files or no results unless `allowEmptyResults` is set: confirmed in the plugin’s [messages](https://raw.githubusercontent.com/jenkinsci/junit-plugin/master/src/main/resources/hudson/tasks/junit/Messages.properties) and `JUnitResultArchiver.java`. The NUnit plugin’s `nunit` step publishes NUnit results, and its `failIfNoResults`, on by default, aborts on no files and fails the build when the reports hold no result: [NUnitPublisher.java](https://raw.githubusercontent.com/jenkinsci/nunit-plugin/master/src/main/java/hudson/plugins/nunit/NUnitPublisher.java).
- `timeout` aborts the build when its limit passes; `retry` reruns its block on any exception and does not catch a user’s abort: the steps’ help files. Multibranch pipelines, shared libraries and scripted pipelines: their pages’ sources. The declarative linter exists: [development.adoc](https://raw.githubusercontent.com/jenkins-infra/jenkins.io/master/content/doc/book/pipeline/development.adoc).

- The chapter’s Jenkinsfile passed the declarative linter of a local Jenkins 2.568.3, and its options, `stash`, `unstash`, stage `environment`, credential bindings and both `archiveArtifacts` calls ran in a pipeline on that controller’s built-in node. In that run, a pattern list whose mapping file and symbols zip matched nothing archived the files that matched and did not fail the build.
- The NUnit plugin, version 648.vdc8c6431f464, recorded one passed test from Unity’s results file of a one-test run, and failed the build for the file of a run that executed no test, with “No test report files were found or the NUnit input XML file contained no tests.”
- For a results file that holds no test, `nunit` throws `hudson.AbortException`, “No test report files were found or the NUnit input XML file contained no tests.”, which ends its `post` block: in the local Jenkins, an `archiveArtifacts` placed after it did not run, and one placed before it archived the logs. With no results file at all, the installed version printed “FATAL: No NUnit test report files were found.” and let the next step run. A `when`-gated stage with `deleteDir()` emptied the workspace, `Library` included, before the next stage of its branch.

### ci-secrets-signing

- `withCredentials` binds each credential to an environment variable inside its block; single quotes leave the expansion to the shell, and Groovy interpolation exposes the value to process listings; printed secrets are masked; masking can be circumvented by anyone who can edit the pipeline, and mangled forms are masked on a best-effort basis for common shells; build tools in debug mode may print the environment; on Linux, other processes of the account can read it: confirmed in the step’s [help](https://raw.githubusercontent.com/jenkinsci/credentials-binding-plugin/master/src/main/resources/org/jenkinsci/plugins/credentialsbinding/impl/BindingStep/help.html). In the local Jenkins, a secret passed to `sh` in a double-quoted string drew the warning “A secret was passed to "sh" using Groovy String interpolation, which is insecure.”
- A transformed secret is masked only in the forms the plugin knows: narrowed. The container’s sources, a [blog post](https://raw.githubusercontent.com/jenkins-infra/jenkins.io/master/content/blog/2019/02/2019-02-21-credentials-masking.adoc) of 2019 that printed a password through `base64` and `jenkinsfile.adoc`, which says that a mangled credential is no longer masked, gave base64 as the example. The plugin has masked a secret’s base64 encodings, standard and URL-safe, since a commit of 2023-09-06, “Add base64 masking”: [Base64SecretPatternFactory.java](https://raw.githubusercontent.com/jenkinsci/credentials-binding-plugin/master/src/main/java/org/jenkinsci/plugins/credentialsbinding/masking/Base64SecretPatternFactory.java). In the local Jenkins, with credentials-binding 728.v902a_273b_8947, a bound token’s base64 was masked, a Basic authorization header built from it showed the user name and masked the rest, and the token’s hexadecimal, capitals, reversed and percent-encoded forms appeared in the clear. The chapter’s example and the first `ci-secret-masking` variant use hexadecimal.
- A secret file is written to a private temporary directory, deleted when the block ends: [AbstractOnDiskBinding.java](https://raw.githubusercontent.com/jenkinsci/credentials-binding-plugin/master/src/main/java/org/jenkinsci/plugins/credentialsbinding/impl/AbstractOnDiskBinding.java); in the local run, the bound file was readable inside the block and gone after it. The `credentials()` helper and its `_USR` and `_PSW` variables: `syntax.adoc`.
- `PlayerSettings.Android.useCustomKeystore`, `keystoreName`, `keystorePass`, `keyaliasName` and `keyaliasPass`: confirmed in [PlayerSettingsAndroid.bindings.cs](https://raw.githubusercontent.com/Unity-Technologies/UnityCsReference/6000.3.11f1/Editor/Mono/PlayerSettingsAndroid.bindings.cs), lines 624 to 680. That a project keeps the keystore but not its passwords: chapter 10’s evidence, run 2, whose build in a later session failed at signing until a script set them. The probe’s builds, which set all four, signed.
- The temporary keychain’s commands, `create-keychain` (its `-p` called insecure), `set-keychain-settings -lut`, `unlock-keychain`, `import` with `-k`, `-P` (a GUI prompt without it) and `-T`, `set-key-partition-list` (codesign needs `apple:` in the list, and the keychain’s password is required), `list-keychains -s` and `delete-keychain` (which also removes it from the search list): confirmed in Apple’s [security.1](https://raw.githubusercontent.com/apple-oss-distributions/Security/main/SecurityTool/macOS/security.1) and in the Mac’s installed manual, and run on the Mac.
- Xcode 16 keeps downloaded profiles in `~/Library/Developer/Xcode/UserData/Provisioning Profiles`: confirmed in the [Xcode 16 release notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-16-release-notes). App Store Connect API keys carry a role, team keys reach all apps, and a compromised key is revoked: [Apple’s page](https://developer.apple.com/documentation/appstoreconnectapi/creating-api-keys-for-app-store-connect-api).
- Unity’s license: activation with `-serial`, `-username` and `-password` and return with `-returnlicense`, for Unity Pro and not for Unity Personal (“The following procedures don’t apply to Unity Personal”), on the 6000.3 page [Manage your license through the command line](https://docs.unity3d.com/6000.3/Documentation/Manual/ManagingYourUnityLicense.html); floating licensing, where “the server removes a license from the pool” when an Editor starts on a connected machine and “When the last instance of a Unity Editor is closed on the client computer, the license is released”, on the [licensing overview](https://docs.unity3d.com/6000.3/Documentation/Manual/LicenseOverview.html).

## Narrowed or cut

- **Masking.** The container’s sources gave base64 as a form that escapes masking. The plugin has masked it since 2023, so the chapter’s example and its first `ci-secret-masking` variant use hexadecimal, which a local Jenkins printed in the clear.
- **Versions and build numbers.** The chapter explained them in place. It now takes the rules from chapter 10 and keeps what the pipeline adds, the `VERSION` file and the base number, and its sentence that a `yyMMddHHmm` stamp is above Google Play’s maximum went, since chapter 10 weighs time-based numbers itself.
- **The environment.** The build script no longer writes a `GAME_ENV_` define into the shared Player settings, the older way in chapter 10’s terms; it builds a profile, whose defines choose the environment.
- **The build stamp.** Chapter 10’s `StoreBuild` writes it; `CiBuild` keeps that order and leaves the stamp out, which the chapter says.
- **IL2CPP’s build cache.** Named as part of `Library/Bee`, from the probe’s Android build log, with no claim about other platforms.
- **Case-sensitive file systems.** Stated as a difference between agents; one Mac was checked.
- **The key’s partition list.** The script allows `apple:` alone, which the manual names for `codesign` and which the test found enough, in place of `apple-tool:,apple:`.

## Where the outline fell short

- **Unity’s results are NUnit XML.** The outline named Jenkins’s `junit` step, which reads JUnit XML. The chapter publishes Unity’s results with the NUnit plugin’s `nunit` step, whose default failed a build with a results file that held no test.
- **Zero tests exit with 0.** In the Test Framework’s runner, a run that executed no test returns the success code, and its results file says `Passed`, which makes the first book’s “zero tests is not a pass” a check the pipeline has to make itself.
- **`BuildPlayer` fails in three ways.** It returns a report, returns null, or throws, and exits the Editor itself on an unexpected exception; a failed report’s result can be `Unknown`. The build script handles all of them.
- **No `-quit` for tests.** The Test Framework’s runner ends the Editor itself, and Unity’s page for it says that `-quit` is not supported while tests run.
- **Parameters for environment and build type.** The outline asked for both. Chapter 10 fixes them together in a build profile, so the Jenkinsfile takes one parameter that names the variant; two would allow a release build against staging.
- **The mapping file.** The outline lists it among the artifacts, and the container’s Jenkinsfile archived the symbols zip without it. Unity writes it beside the bundle, and the Android `success` archive now lists it.
- **Chapter 10’s search of the store build.** Chapter 10 left it to this chapter; the merge added `ci/check-store-hosts.sh`, run before each upload.
- **Handing the project between agents.** Chapter 6 promised it. `stash` is meant for small files, so the chapter hands over only the build’s stamp, keeps the Unity export and the archive on one Mac, and names an artifact repository for large handovers.
