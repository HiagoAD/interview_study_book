# Evidence for chapter 08: Backend clients: HTTP, sessions, and data contracts

What Phase 26 checked the chapter’s claims against, and where the outline was wrong. [PLAN.md](../PLAN.md), under “Decisions: evidence”, says what counts as evidence. Codex was close to the end of its allowance, so the session gathered the evidence itself under the plan’s fallback, rule A, and wrote the receipts in the checker’s format: 190 receipts for 111 claims, none failed on re-fetch (114 documentation, 18 shipped files, 58 from runs). The session’s teacher’s read took the place of the blind review; what it caught is at the end.

## Checked, and against what

### http-semantics

- GET and HEAD are safe; PUT, DELETE and the safe methods are idempotent; an idempotent request can be repeated after a communication failure; a client should not repeat a non-idempotent request unless it knows the request is idempotent by design or that the first one was not applied: confirmed. Source: https://www.rfc-editor.org/rfc/rfc9110.html, sections 9.2.1 and 9.2.2.
- 401 means the request was not applied for lack of valid credentials and carries `WWW-Authenticate`; 403 means understood and refused, and a client should not repeat it with the same credentials; a server may answer 404 to hide a forbidden resource: confirmed. Source: RFC 9110, sections 15.5.2, 15.5.4 and 15.5.5.
- Bearer token errors: `invalid_token` for an expired, revoked or malformed token, with a 401, after which the client may get a new token and retry; `insufficient_scope` with a 403: confirmed. Source: https://www.rfc-editor.org/rfc/rfc6750.html, section 3.1.
- An unrecognized status code is treated as the x00 code of its class: confirmed. Source: RFC 9110, section 15.
- 201, 204 (no content), 304, 400, 409, 412, 422, 500, 502, 503 and 504 as the chapter’s table describes them: confirmed. Source: RFC 9110, section 15. 429 and its optional `Retry-After`: confirmed. Source: https://www.rfc-editor.org/rfc/rfc6585.html, section 4. `Retry-After` is a date or a number of seconds, and a 503 may carry it: confirmed. Source: RFC 9110, section 10.2.3.
- `ETag`, `If-None-Match` leading to 304 for stored responses, and `If-Match` preventing the lost update of parallel clients: confirmed. Source: RFC 9110, sections 8.8.3, 13.1.1, 13.1.2 and 13.1.
- `Content-Type`, `Accept` and `Authorization` as described: confirmed. Source: RFC 9110, sections 8.3, 12.5.1 and 11.6.2.
- A request whose timeout fires while its body arrives ends as `ConnectionError` with status 200: confirmed by run 1 (see Runs).
- The chapter’s `HttpStatusMapping` maps 451 to `Rejected`, 299 to `Ok`, 503 to `ServerError` and 302 to `Unknown`: confirmed by the .NET 8 harness and, for 451, 409 and 204, by run 3.

### http-unity-clients

- `UnityWebRequest` is created and read on the main thread: confirmed by run 2, where `Create` and `get_result` on a worker thread threw `UnityException`. Unity’s reference states no thread rule for the class, so the chapter rests on the run.
- `SendWebRequest` can be called once per object: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Networking.UnityWebRequest.SendWebRequest.html, and run 2 (a second call threw `InvalidOperationException`).
- `await` works on `SendWebRequest` in Unity 6.3: confirmed. `UnityEngine.AsyncOperationAwaitableExtensions.GetAwaiter(AsyncOperation)` calls `Awaitable.FromAsyncOperation` and is marked `ExcludeFromDocs`: `monodis` of `Unity.app/Contents/Resources/Scripting/Managed/UnityEngine/UnityEngine.CoreModule.dll` relative to `6000.3.11f1/`. Each awaiting method resumed on the main thread in runs 1 to 3.
- Cancelling the token given to `Awaitable.FromAsyncOperation` aborts the request, not only the wait, and an `await` on an aborted request throws `OperationCanceledException`: confirmed by run 2 only; the reference is silent.
- The meanings of the four `Result` values: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Networking.UnityWebRequest.Result.html. The examples in the chapter’s table: runs 1 and 2.
- A 304 is `Success` with an empty body, a `ProtocolError` keeps the error body readable, and `responseCode` can be 200 on a `ConnectionError`: confirmed by runs 1 and 2.
- `timeout` is in seconds, 0 by default, and ends in the error “Request timeout”: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Networking.UnityWebRequest-timeout.html. In the Editor it bounded the whole transfer: run 1. On iOS the Trampoline passes it to `NSURLRequest`’s `timeoutInterval`: `PlaybackEngines/iOSSupport/Trampoline/Classes/Unity/UnityWebRequest.mm:441`, which Apple defines as idle time: https://developer.apple.com/documentation/foundation/nsurlrequest/timeoutinterval. How the iOS player behaves was not run; the chapter says the property may bound a different interval there.
- `Abort` ends with the error “Request aborted”: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Networking.UnityWebRequest.Abort.html, and run 2.
- `Dispose` is to be called whether the request succeeded or failed, in a `using` statement: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Networking.UnityWebRequest.Dispose.html. The finalizer calls `DisposeHandlers` and `InternalDestroy`: `monodis` of `UnityEngine.UnityWebRequestModule.dll`.
- `disposeDownloadHandlerOnDispose` defaults to true: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Networking.UnityWebRequest-disposeDownloadHandlerOnDispose.html. Reading the handler after `Dispose` threw `NullReferenceException` (“DownloadHandler has already been destroyed”), and with the property false the text stayed readable: run 2.
- `CertificateHandler.ValidateCertificate` is called for each leaf certificate, and custom validation is implemented on Android, iOS and desktop platforms among others: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Networking.CertificateHandler.html and its `ValidateCertificate` page. Pinning to more than one key, one of them a backup outside the current chain: https://www.rfc-editor.org/rfc/rfc7469.html, written for browsers’ public key pinning, whose backup-pin rule the chapter applies to an app’s pins.
- `HttpClient` instances are to be reused to avoid port exhaustion: confirmed. Source: https://learn.microsoft.com/en-us/dotnet/fundamentals/networking/http/httpclient-guidelines. Its default timeout of 100 seconds, `TaskCanceledException` for a timeout and for a cancellation alike, resuming on the main thread, and leaving it after `ConfigureAwait(false)`: run 1, in the Editor’s Mono. The IL2CPP class library’s `HttpClient` also implements `Timeout` with `CancellationTokenSource.CancelAfter`: `monodis` of `unityaot-macos/System.Net.Http.dll`.
- `HttpClientHandler` delegates to `SocketsHttpHandler` in the Editor’s class library and creates a `MonoWebRequestHandler`, built on `HttpWebRequest`, in the IL2CPP class libraries: `monodis` of `MonoBleedingEdge/lib/mono/unityjit-macos/System.Net.Http.dll`, `unityaot-linux/System.Net.Http.dll` and `unityaot-macos/System.Net.Http.dll`, and run 1 for the Editor.
- With “Allow downloads over HTTP” at `NotAllowed`, the Editor’s `UnityWebRequest` refused a plain HTTP address on the local network (`InvalidOperationException`, “Insecure connection not allowed”) and let `127.0.0.1` and `localhost` through, and `HttpClient` fetched the same network address: run 2.
- ATS is enforced for the URL Loading System and does not apply to lower-level networking interfaces: confirmed. Source: https://developer.apple.com/documentation/security/preventing-insecure-network-connections.
- Android honors its cleartext flag on a best-effort basis, and the Socket API is not expected to: confirmed. Source: https://developer.android.com/guide/topics/manifest/application-element.
- Unity’s Android player carries libcurl 8.10.1 and the string “Insecure connection not allowed” in `libunity.so`, and neither it nor the classes in `classes.jar` name `NetworkSecurityPolicy` or `isCleartextTrafficPermitted`: `strings` of `PlaybackEngines/AndroidPlayer/Variations/il2cpp/Release/Libs/arm64-v8a/libunity.so` and a search of the unzipped `Variations/il2cpp/Release/Classes/classes.jar`. The chapter says a device test was not made.

### http-sessions

- Refresh tokens obtain new access tokens when the current one expires, and access tokens may be shorter-lived; an access token is usually opaque to the client; `expires_in` counts from when the response was generated; a client given a new refresh token discards the old one: confirmed. Source: https://www.rfc-editor.org/rfc/rfc6749.html, sections 1.4, 1.5, 5.1 and 6.
- `invalid_grant` covers a refresh token that is invalid, expired or revoked, with a 400 unless stated otherwise: confirmed. Source: RFC 6749, section 5.2.
- Public clients’ refresh tokens must be sender-constrained or rotated; rotation invalidates the used token; a reused invalidated token makes the server revoke the active one and forces a new grant: confirmed. Source: https://www.rfc-editor.org/rfc/rfc9700.html, sections 2.2.2 and 4.14.2.
- The `Date` header carries the time the message was originated: confirmed. Source: RFC 9110, section 6.6.1.
- A JWT is a compact, URL-safe format for claims, a JSON object that is signed or encrypted, in a compact serialization: confirmed. Source: https://www.rfc-editor.org/rfc/rfc7519.html.
- `PlayerPrefs` is stored without encryption and not for sensitive data, in shared preferences on Android and through `NSUserDefaults` on iOS: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/PlayerPrefs.html.
- Auto Backup includes shared preferences files by default, for apps that target API 23 or higher: confirmed. Source: https://developer.android.com/identity/data/autobackup. `android:allowBackup` defaults to true: https://developer.android.com/guide/topics/manifest/application-element. Neither the probe’s Gradle export nor the Editor’s `AndroidPlayer/Apk` files and Gradle templates set it, so a default Unity game is backed up.
- Keychain items marked `ThisDeviceOnly` do not migrate to a new device: confirmed. Sources: https://developer.apple.com/documentation/security/ksecattraccessiblewhenunlockedthisdeviceonly and https://developer.apple.com/documentation/security/ksecattraccessibleafterfirstunlockthisdeviceonly. The Android Keystore makes keys more difficult to extract: https://developer.android.com/privacy-and-security/keystore.
- Secrets built into a distributed app are not confidential: confirmed. Source: https://www.rfc-editor.org/rfc/rfc8252.html, section 8.5.
- Play Integrity checks for the genuine app on a genuine device and works best alongside other signals: confirmed. Source: https://developer.android.com/google/play/integrity/overview. App Attest lets a server grant access more confidently, and one compromised device can serve assertions to many: https://developer.apple.com/documentation/devicecheck and https://developer.apple.com/documentation/devicecheck/assessing-fraud-risk.
- Apple lists logging out of an account associated with notifications as a time to call `unregisterForRemoteNotifications`: confirmed. Source: https://developer.apple.com/documentation/uikit/uiapplication/unregisterforremotenotifications%28%29.
- The chapter’s `SessionClient` sends one refresh for concurrent 401s, retries with the new token, starts no refresh for a late 401 with an old token, keeps the session when the refresh gets no response, signs out when it is rejected, refreshes ahead of expiry, and returns a second 401: confirmed by the .NET 8 harness, and against a server that rotates refresh tokens by run 3.

### http-dtos

- `JsonUtility` follows Unity’s serializer: fields only, no properties, dictionaries, multidimensional or jagged arrays or nested containers; a base-typed field keeps the base class’s fields; for unknown types, read the common fields first: confirmed. Sources: https://docs.unity3d.com/6000.3/Documentation/Manual/json-serialization.html and https://docs.unity3d.com/6000.3/Documentation/Manual/script-serialization-rules.html.
- `FromJson` runs field initializers and the default constructor, fields missing from the JSON keep those values, and it can be called from background threads; `ToJson` of an array does not produce a JSON array: confirmed. Sources: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/JsonUtility.FromJson.html and `JsonUtility.ToJson.html`.
- `JsonUtility` behavior in Unity 6.3: a top-level array throws `ArgumentException` (“JSON must represent an object type.”), `ToJson` of an array writes `{}`, unknown fields are skipped, `null` becomes 0 or an empty string, `"12"` fills an `int` and 5.7 fills it with 5, names match case-sensitively, enum names are not read, an unknown enum number is kept, a `long` above 2^53 stays exact, the `float` 0.1 is written as 0.10000000149011612, `[SerializeReference]` writes Unity’s reference format, and `DateTime` is not serialized: run 1.
- Unity’s Newtonsoft package 3.2 corresponds to Newtonsoft.Json 13.0.2: confirmed. Source: https://docs.unity3d.com/Packages/com.unity.nuget.newtonsoft-json@3.2/manual/index.html. It carries an AOT build: the 3.2.2 package’s `CHANGELOG.md` and `Runtime/AOT/Newtonsoft.Json.dll` in the local package cache.
- Json.NET 13.0.2 from that package, in .NET 8: unknown members are ignored by default and throw with `MissingMemberHandling.Error`; an unknown enum name throws; a `long` stays exact and a `double` loses 2^53 + 1; “Z” reads as UTC and no offset as unspecified; `null` for an `int` throws; names match in any case: the .NET 8 probe (see Runs).
- Minimal, the default for IL2CPP, removes no user-written code; Low searches user assemblies under a condition, and Medium and High search all assemblies; the linker cannot always detect uses of reflection: confirmed. Sources: https://docs.unity3d.com/6000.3/Documentation/Manual/managed-code-stripping-configure.html and https://docs.unity3d.com/6000.3/Documentation/Manual/managed-code-stripping-preserving.html.
- `[Preserve]` on a type keeps the type and its default constructor, and on a property its accessors; `preserve="all"` in `link.xml` keeps a type and all its members: confirmed. Sources: https://docs.unity3d.com/6000.3/Documentation/Manual/managed-code-stripping-preserving.html and https://docs.unity3d.com/6000.3/Documentation/Manual/managed-code-stripping-xml-formatting.html.
- Json.NET maps dictionaries to JSON objects: confirmed. Source: https://www.newtonsoft.com/json/help/html/SerializationGuide.htm. Its handling of properties, nullable values, converters and type names was not fetched; the chapter names them as the library’s features.
- Reflection-only serialization can need code the AOT compiler does not detect; for generic instances not found at build time, IL2CPP generates slower code that works with any type parameter: confirmed. Source: https://docs.unity3d.com/6000.3/Documentation/Manual/scripting-restrictions.html.
- Implementations agree exactly on integers within ±(2^53 − 1) because many use IEEE 754 doubles: confirmed. Source: https://www.rfc-editor.org/rfc/rfc8259.html, section 6. RFC 3339 is a profile of ISO 8601, and “Z” is a UTC offset of 00:00: https://www.rfc-editor.org/rfc/rfc3339.html.
- Google Play Billing reports prices in micro-units, a million to one unit of the currency: confirmed. Source: https://developer.android.com/reference/com/android/billingclient/api/ProductDetails.OneTimePurchaseOfferDetails.
- The chapter’s DTOs and mapper, read through `JsonUtility`, skipped the unknown kind and the item without an id and converted an offset date to UTC: run 3 and the .NET 8 harness.

## Rests on documentation alone

- HTTP and OAuth semantics are what the RFCs define. A given backend may use status codes differently, rotate refresh tokens or not, and return `invalid_grant` with another status; the chapter states the RFCs’ rules and the client’s design, not any one backend’s behavior.
- Play Integrity and App Attest are described from their overviews; no attestation was run.
- ATS’s scope, Android’s cleartext flag, the Keychain’s migration rule, the Keystore and Auto Backup rest on Apple’s and Android’s pages; no device was used.
- `HttpClient`’s behavior in an IL2CPP player rests on the class libraries’ IL. The runs exercised the Editor’s `SocketsHttpHandler`, not `MonoWebRequestHandler`.

## Narrowed or cut

- The outline’s “an `http://` development server works in the Editor and fails on a device” holds only for a server reached at `localhost` or `127.0.0.1`, which Unity’s check lets through in the Editor while a phone needs the machine’s network address, which the check refuses. With a network address, the Editor refuses it too. The chapter says so, and points to chapter 6 for the setting’s other values.
- Android’s cleartext default was not claimed to stop `UnityWebRequest`: Unity’s player sends it through libcurl and does not refer to the policy, and no device test was made. The chapter states both.
- `timeout` was narrowed to a guard against a stalled request: the Editor applied it to the whole transfer, while the iOS Trampoline hands it to an idle timeout.
- The outline’s “unregister the push token” at logout became detaching the token from the account on the backend while the session is still valid, as chapter 4 set out, with Apple’s reference cited for `unregisterForRemoteNotifications` on iOS.
- Stripping “empties DTOs” was narrowed to members that only reflection reaches possibly being removed at Low, Medium or High, since Minimal, the IL2CPP default, removes no user-written code. No IL2CPP player build was made to show the symptom.
- No lifetime figures for access or refresh tokens: they are the backend’s choice.

## Where the outline fell short

- It asked to verify `UnityWebRequest`’s thread rules; the reference gives none, and the run showed that creating and reading a request are main-thread only.
- It did not know that Unity 6.3 can `await` `SendWebRequest` directly, through an extension the reference leaves out, or that cancelling `Awaitable.FromAsyncOperation`’s token aborts the request.
- It did not mention that a `ConnectionError` can carry status 200, that a 304 is a `Success` with no body, or that the download handler goes with the request on `Dispose`; each changes how an adapter is written, and each became a question.
- It treated `HttpClient` as one implementation. The Editor and IL2CPP players run different handlers under it, and neither is covered by Unity’s HTTP setting, ATS or, by Android’s own account, the cleartext flag.
- It listed `JsonUtility`’s limits but not its leniency: `null` as 0, strings read as numbers, case-sensitive names and enums read only as numbers, which is why the chapter keeps enum values as strings in DTOs.
- Logout needs an order, since detaching the push token and revoking the refresh token need the session that clearing it ends.

## Runs

All runs were made on 2026-09-25 in the session’s scratch folder, against a local Python HTTP server; the probe project was not changed.

- Run 1: a new Unity 6000.3.11f1 project, in batch mode, with an Editor script covering `UnityWebRequest` results, timeouts and HTTP status handling, `HttpClient` in the Editor, and `JsonUtility` cases. An abort ended the `UnityWebRequest` part early, because the `await` threw; run 2 repeated the rest.
- Run 2: the same project: the plain-HTTP check against `127.0.0.1`, `localhost` and the machine’s network address for each value of the setting, `HttpClient` against the network address, abort and token cancellation, `Dispose` and the download handler, worker-thread access, ETags and request headers.
- Run 3: the chapter’s C#, extracted from the chapter file byte for byte, compiled in the same project with no error or warning, and run against the server: the transport’s results, cancellation, ETags and headers, the server clock, `SessionClient` against an endpoint that rotates refresh tokens and revokes on reuse (three concurrent 401s, one refresh, three successes), the offers mapping through `JsonUtility`, and the client policy.
- .NET 8: a probe of Json.NET using the `Newtonsoft.Json.dll` of the cached package 3.2.2, and a harness of 31 checks over the chapter’s code without its `UnityWebRequest` transport, with stand-ins for `JsonUtility` and `Application.version` and a single-threaded synchronization context pumped like Unity’s main thread. Removing the `IsCompleted` check from `RefreshAsync` failed the check that a transport completing at once does not reuse a finished refresh.

## The teacher’s read

The session read the chapter as a teacher once it was drafted, in place of the blind review, each claim against its receipt and each question against the standard. It changed:

- The advice for stripped DTOs. `[Preserve]` on a type keeps the type and its default constructor, not the members Json.NET fills, so the chapter now names `preserve="all"` in `link.xml`, or `[Preserve]` on each member, in the prose and in the explanation of the question on stripping.
- A distractor in `http-min-version`, “Treat the client as up to date, and stop checking for the rest of the session”, which described what the chapter’s own `ClientPolicy` does and was defensible as correct. It became a retry loop that blocks launch.
- A distractor in `http-401-403`, “Keep the answer…”, which read like the code comment that returns the second 401 to the caller. It became “Ignore the 401…”.
- `Abort`’s result, stated as `ConnectionError` in general, while Unity’s reference allows any of the three error values; the chapter now reports what the tests showed.
- Overstatements: that anyone holding an access token can decode it (true of a signed JWT), that many backends rotate refresh tokens (now what RFC 9700 requires), that both platforms call attestation one signal among others (Apple’s wording is weaker; the chapter and the glossary now say neither presents it as proof), that `JsonUtility` ignores unknown enum names (tested with a known name only), that no backend produces `[SerializeReference]`’s format, and that the Socket API does not honor the cleartext flag “at all”.
- Precision: the session layer ends on a 400 or a 401 from the refresh endpoint, as its code does, rather than on `invalid_grant` alone; the Auto Backup claim now says that Unity’s export leaves `allowBackup` at its default; Low stripping searches user assemblies only under a condition; the tests behind the results table ran in the Editor; the logout steps now come in order, since detaching the push token needs the session, as chapter 4 set out.
- Writing: an inverted sentence about status codes, a fragment, and four phrases that steered the reader instead of informing, which the avoid-ai-writing detector does not catch. Its per-section runs rated each part and the new glossary entries “Clean” or “Minimal AI signals”; what it flagged were known false positives: low vocabulary diversity, `{#id}` read as hashtags, “genuine” in Google’s literal sense of an unmodified app, and “serves as” matched inside “serve assertions”.
