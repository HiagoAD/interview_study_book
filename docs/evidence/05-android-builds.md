# Evidence for chapter 05: Android builds: Gradle, manifests, and dependencies

What Phase 23 checked the chapter's claims against, and where the outline was wrong. [PLAN.md](../PLAN.md), under “Decisions: evidence”, says what counts as evidence.

## Where it was checked

Phase 23 ran in a Linux cloud container, not on the machine with the 6000.3.11f1 Editor, the probe project and Xcode. The container's network policy denied `docs.unity3d.com`, `download.unity3d.com`, `dl.google.com` (the Android SDK, and every download from Google's Maven repository, which redirects there), `docs.gradle.org`, `support.google.com`, `docs.cloud.google.com` and GitHub's web pages. So the phase's own task, building the probe's Gradle export with the Editor's Gradle, could not be done: there was no export, no Unity template to fill, no Android SDK and no Android Gradle Plugin. What stood in for it is below, and the chapter was narrowed to what these sources carry. The chapter adds no Unity documentation links, since none could be checked.

## Checked, and against what

Checked, and against what, by section. `gradle-project`: Unity's C# reference source at tag `6000.3.11f1` (`IPostGenerateGradleAndroidProject.OnPostGenerateGradleAndroidProject(string path)` in `UnityEditor.Android`; `EditorUserBuildSettings.exportAsGoogleAndroidProject` and `buildAppBundle`); the source of Unity's Mobile Notifications package 2.5.0, for Unity 6000.0 and later (`AndroidProjectFilesModifier` with `Setup`, `SetData`, `Outputs.AddManifestFile`, `AddFileWithContents`, `OnModifyAndroidProjectFiles`, `GetData`, `SetFileContents`, `SetManifestFile` and `AndroidManifestFile`; its manifest in `unityLibrary/mobilenotifications.androidlib`; its 2.4.0 changelog line on the incremental build; `api files('../libs/unity-classes.jar')`, which places the jar in `unityLibrary/libs`); Unity's `uaal-example` README, which requires 6000.0.0b16 and describes the library part as holding all source and plugins and the launcher part the app's representation, with Export Project in the Build Profiles window; EDM4U's source at 1.2.189 (Unity's templates under `Tools/GradleTemplates`, custom copies under `Assets/Plugins/Android`, the `**DEPS**` token, repositories in `settingsTemplate.gradle` from Unity 2022.2, the `id 'com.android.application' version '…' apply false` form, and the `packaging` changes of 1.2.184 and 1.2.185); Google's Play plugins README for the Custom Main Gradle Template checkbox in Publishing Settings; Android's release notes for AGP 8.10, its `AarMetadata` reference and its command-line build page. Gradle 8.13, OpenJDK 17, NDK r27c and SDK platforms up to 36 come from Phase 19's reference paragraph; AGP 8.10.0, the placement of plugins, the `jniLibs` without `libil2cpp.so` and `unityLibrary/symbols/<abi>/` from Phase 20's exports; the five template names from the outline's listing of 6000.3's templates folder, three of them also in EDM4U.

`gradle-manifest-merge`: Android's page on merging manifests (priorities, match keys, conflicts, the markers and which file they are read from, `<manifest>` attributes, intent filters, `uses-sdk` and `overrideLibrary`, build files overriding manifest values, the report's path), Android 12's behavior changes (the `android:exported` rule, the “Manifest merger failed” message, the refused install), and bundletool 1.17.2's help for `dump manifest`. EDM4U's settings give `Assets/Plugins/Android/AndroidManifest.xml` as the custom main manifest.

`gradle-dependencies`: Gradle 8.13 from `services.gradle.org` on a local Maven repository holding `netcore` 1.2.0 and 2.0.0, where 2.0.0 renames a method, and two SDK stand-ins built against each. It printed the tree and the `dependencyInsight` lines the chapter shows, built the app and failed at run time with `NoSuchMethodError`; `failOnVersionConflict()` failed resolution naming the module and both versions; `strictly '1.2.0'` lowered 2.0.0 and moved the `NoSuchMethodError` to the other stand-in; a constraint raised 1.2.0 to 2.0.0; an exclusion ended in `NoClassDefFoundError`; dependency locking wrote `gradle.lockfile` and rejected the version that moved. D8 from R8 8.10.21 rejected a class present in two inputs as “defined multiple times”. Android's page on dependency errors names the local and remote binary dependency case; EDM4U's README and settings dialog give the resolver's two modes, the template markers, Patch mainTemplate.gradle and Delete Resolved Libraries.

`gradle-r8-symbols`: R8 8.10.21, from Google's R8 release bucket, run in class-file mode and in DEX mode at `--min-api 25` on the chapter's Java, which compiles unchanged with javac 21 at `--release 17 -Xlint:all -Werror`. With no rule it removed the three classes; with a rule for `StoreBridge` alone it renamed the interface to `a.a`, renamed its methods, dropped their parameters and rewrote the kept method's signature; the chapter's two rules fixed it. Retrace restored the inlined `ReceiptFormatter.format` frame, and with the next build's mapping it turned the same frame into one frame at line 10, with no warning; the two mappings carry different `pg_map_id` values. Unity's reference source shows `AndroidJavaProxy(string)` looking the interface up by name and `Invoke` dispatching by method name, reporting “No such proxy method” otherwise, and `PlayerSettings.Android.minifyRelease` and `minifyDebug`. The notifications package keeps its bridge with consumer rules, and its 2.4.1 release (2025-05-28) added a missing one. Android's pages on R8, keep rules, troubleshooting (the mapping file travels in an app bundle and is overwritten by each build), retrace and native symbols back the rest.

`gradle-packaging-signing`: Android's pages on app bundles, bundletool, app signing, Digital Asset Links, Play Games Services setup (the SHA-1 of the app signing key, one client per certificate), `apksigner`, `adb` (`pm path`), build configuration (`compileSdk`, `minSdk`, `targetSdk`), `<uses-sdk>`, and Google Play's target API level requirement, read in September 2026; bundletool 1.17.2's help (`build-apks`, `install-apks`, `--mode=universal`, signing with the debug key when no keystore is given); Unity's reference source for the keystore properties, `minSdkVersion` and `targetSdkVersion`, the minimum supported level of 25, and `AndroidApiLevelAuto`, “Set target API level to latest installed”.

## Resting on other sources, narrowed, or cut

No Gradle build of a Unity project ran, so every claim about the generated project rests on Phase 20's exports, Unity's reference source and packages, EDM4U and Google's plugin READMEs. That a non-exported build compiles `libil2cpp.so` inside Gradle was not checked, so the chapter says it of exported projects only. The order of the three manifest sources rests on Android's rule that libraries rank in dependency order and on Gradle 8.13's consumer-first artifact order in a probe (a module's jar before its dependencies'), not on an AGP build. `Assets/Plugins/Android/proguard-user.txt` rests on the Play Games plugin's README, written for an older Unity whose Publishing Settings said User Proguard File; the chapter names the file and not the checkbox. The dependency tree and insight lines came from a plain Java project, so the chapter shows the tree without its configuration header. R8 8.10.21 is a release of AGP 8.10's line; the version AGP 8.10.0 bundles is in its POM, behind `dl.google.com`. Cut: API key restrictions from the list of places that need the app signing key's fingerprint, since Google Cloud's page could not be fetched; the Unity UI names of the minify, keystore and target level settings, which the chapter gives through their scripting API instead; and any Unity documentation link.

## Where the outline fell short

Where the outline fell short: it said the application's manifest wins conflicts, and Android's rule is that a conflict fails the build unless the higher-priority manifest resolves it with a marker, so `gradle-merge-priority` tests that. It offered three ways to customize the project; the chapter adds that Unity's own package puts its manifest entries in a library module of its own, and that the modifier's `Setup` hands data to the modification step. It listed a keep rule for the class C# calls; R8 showed that the interface an `AndroidJavaProxy` implements needs a rule of its own, with its method names, because Unity looks both up by name. It asked for Play's recovery rules: an upload key is reset through the Play Console, an app signing key is not released, and an app that manages its own key loses its updates with it. Chapter 4 is not written on this branch yet, so the chapter names it in plain text for verified links and runtime permissions.
